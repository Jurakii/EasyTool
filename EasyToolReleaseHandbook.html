EasyTool Release Handbook

What to do after you change something: update one of your tools, add a new one, or ship a new EasyTool. The helpers below fill in the exact version numbers, commands and tools.json lines for you.

Jurakii/EasyTool

The app. Its code, and a release zip for each version.

  • easytool/__init__.pythe version number
  • CHANGELOG.mdwhat changed
  • tools/build_release.pybuilds the zip
Jurakii/Tools

Your tools and the feed every EasyTool reads.

  • tools.jsonwhat users see, and their versions
  • scripts/*.zipyour tools
  • icons/pictures for your site and the list

How an update reaches users

  1. You upload the new zip: to scripts/ for a tool, or to a GitHub release for EasyTool.
  2. You raise its version in tools.json and push.
  3. EasyTool reads tools.json whenever its panel opens or someone presses refresh.
  4. Users see Update on the tool, or the bar offering a new EasyTool.

The id never changes.
EasyTool remembers what's installed by id. A new id is a different tool to it, so the old one would show as installed but missing from the feed.

Version rules

      

        
Versions compare number by number.
0.9.0 → 0.9.1 → 0.10.0 → 1.0.0. So 0.10 is newer than 0.9, and two-part versions like your tools' 1.1 work too (1.1 means 1.1.0).

        
For EasyTool, tools.json and the zip must agree.
The version in the easytool entry has to match __version__ inside the zip. If the zip isn't newer than what someone has installed, the update stops with "isn't newer" and nothing is changed.

        
Never reuse a version number.
EasyTool keeps each version's download. Re-uploading a different zip under the same number won't reach anyone who already downloaded it.

        
There are no downgrades.
EasyTool only offers newer versions. To undo a bad release, publish a fixed one with a higher number.

        
A suggested scheme for EasyTool.
Bump the last number for fixes (0.9.1), the middle one for new features (0.10.0), and go to 1.0.0 when it's out of beta. From then on, leave "pre-release" unticked.

      

    


    
    

      
When something's off

      
Troubleshooting

      

        

          
What you seeLikely causeFix

          
            
A tool update doesn't show upThe version wasn't raised, tools.json isn't pushed, or GitHub's cacheRaise the version, push, wait about 5 minutes, press refresh

            
The EasyTool update bar never appearsThe entry's id isn't exactly easytool, the version isn't higher, the entry is disabled, or the link doesn't end in .zipFix the easytool project in tools.json

            
"The download is EasyTool X, which isn't newer…"__version__ wasn't changed before building, so the zip has the old numberSet the version, rebuild, and swap the zip attached to the release. Nobody could install the bad one, so reusing the number is fine here

            
Update fails with a download errorThe release is a draft, the zip's name differs from the link, or the release isn't published yetOpen the Download link in a browser; it should download the zip

            
A button shows a blank iconIts -image name has no matching file in icons/Rename one to match (see Clean Sweep below)

            
A yellow warning about a source in the panelThat source couldn't be read: you're offline, or tools.json isn't valid JSONHover the warning for details; check tools.json opens in your editor

            
EasyTool says "update it there" instead of updatingThat copy runs from the source folder (next to drag_into_maya.py or in the git repo)Expected: the source copy never overwrites itself. Pull or edit the repo instead

Fixes waiting in your tools

      
Found during testing and left for you to apply. After each one, follow Update one of your tools with a higher version.


      
Clean Sweep shows a blank icon

      
Its button asks for Cleanup.png, but the zip ships icons/CleanSweep.png. In shelves/shelf_CleanSweep.mel, change both lines:

      
        -image "CleanSweep.png"
        -image1 "CleanSweep.png"


      
Assign RGB fails on a second click

      
The window assignRGB still exists from the first click. Close it before creating it again. The lines go just before window -title …, in both buttons' commands and in both .mel files:

      
if (`window -exists assignRGB`)
    deleteUI assignRGB;
